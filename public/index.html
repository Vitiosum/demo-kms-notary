Clever KMS · Transit engine · Vault API

Every deed, its own key.

Each deed in this notary's archive is encrypted with a fresh data key. That key is sealed by a master key that never leaves Clever KMS. PostgreSQL only holds ciphertext and sealed keys: to read a deed, the app has to ask the KMS, every time.

  • AES-256-GCM, one key per deed
  • Master key kept in Clever KMS
  • PostgreSQL encrypted at rest
  • Rotation without re-encrypting

          1. 1

            Rotate

            The KMS adds a new version. New deeds are sealed with it; old deeds still open with theirs. Not one byte of the archive is re-encrypted.

            1. 2

              Re-seal the envelopes

              Each older sealed key goes back to the KMS and returns sealed by the latest version (rewrap). The KMS never hands out the data key and the deeds stay as they are: their body fingerprint does not change.

              1. 3

                Lock the old versions

                Sets min_decryption_version to the latest version: the KMS now refuses to unseal any key sealed by an older one. Open a deed still on an old version to see the refusal, then unlock.
